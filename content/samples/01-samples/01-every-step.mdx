<Explain stage="hook">

Ada sells paper lanterns, and her shop needs a small website. This sample lesson follows her site from a tap on a phone to a finished page.

It is made up, and it exists to test the lesson player: every kind of step appears once, and every lab is drawn once.

</Explain>

<Diagram stage="investigate" lab="request-journey">

Tap through the trip and watch what moves between the phone and the server.

<State title="You type an address">
You type the shop's address and tap Go.
</State>

<State title="Find the server">
The browser looks up where the shop's server is.
</State>

<State title="Send a request">
The browser asks the server for the page. That message is a **request**.
</State>

<State title="The server responds">
The server sends back a **response**, starting with the page's HTML.
</State>

<State title="Fetch the extras">
The HTML links to more files: CSS, images and JavaScript. The browser asks for each one.
</State>

<State title="Draw the page">
With the files in hand, the browser draws the lantern shop on the screen.
</State>

</Diagram>

<Predict stage="predict" run assesses="zz.sample.read">

Ada's shop sign uses this CSS. What will the word look like when the page runs?

```html title="index.html" readonly
<p class="sign">Open today</p>
```

```css title="styles.css" readonly
.sign { font-weight: 700; }
```

<Option id="a" correct feedback="Right. A weight of 700 is bold.">Bold</Option>
<Option id="b" feedback="Italic comes from font-style, not font-weight.">Italic</Option>
<Option id="c" feedback="Nothing here changes the size.">Twice as big</Option>

<Hint>Look at the property name: what does weight describe in a font?</Hint>
<Hint>font-weight sets how thick the letters are. 400 is normal.</Hint>
<Hint>Example: a heading with font-weight: 800 looks extra thick.</Hint>

</Predict>

<Explore stage="investigate" control="gap" values="0,12px,32px" assesses="zz.sample.try">

<Ask>Which value leaves the most space between the lanterns?</Ask>

<Option id="a" feedback="0 puts them right next to each other.">0</Option>

<Hint>Try each value and compare the spaces.</Hint>

</Explore>

<Diagram stage="investigate" lab="flex-axes">

Step through the two axes of Ada's menu bar.

<State title="The main axis">
In a flex row, the main axis runs left to right.
</State>

<State title="The cross axis">
The cross axis runs top to bottom.
</State>

<State title="Centre on the cross axis">
align-items: center lines the items up along the middle of the cross axis.
</State>

<State title="Turn it into a column">
In a column the main axis runs top to bottom instead.
</State>

<State title="Centre a column">
Now align-items: center works left to right.
</State>

</Diagram>

<Explore stage="investigate" lab="page-load" control="Connection" values="Fast,Slow" assesses="zz.sample.read">

Load the page on a fast connection, then on a slow one, and watch the files arrive.

<Ask>On a slow connection, which file arrives last?</Ask>

<Option id="a" feedback="The HTML is always the first file.">index.html</Option>
<Option id="b" correct feedback="Yes. The photo is by far the biggest file.">The photo</Option>
<Option id="c" feedback="The styling arrives early so the page can be drawn.">styles.css</Option>

<Hint>Watch the list of files as the page loads.</Hint>
<Hint>Bigger files take longer on a slow connection.</Hint>
<Hint>Example: a news site often shows its headline before its photos.</Hint>

</Explore>

<Diagram stage="investigate" lab="url-anatomy">

Step through the parts of an address for Ada's shop.

<State title="The scheme">
https says how the browser and the server will talk.
</State>

<State title="The domain">
The domain names the shop's server.
</State>

<State title="The path">
The path names the page on that server.
</State>

<State title="The query">
The query adds details, such as a search for gold lanterns.
</State>

</Diagram>

<Explore stage="investigate" lab="http-exchange" control="Request" values="The home page,A photo,A missing page,A form" assesses="zz.sample.read">

Send each request to Ada's server and read the status code that comes back.

<Ask>Which request gets 404 Not Found?</Ask>

<Option id="a" feedback="The home page exists, so the server answers 200 OK.">The home page</Option>
<Option id="b" correct feedback="Right. 404 means the server has no page at that address.">A missing page</Option>
<Option id="c" feedback="A sent form usually gets a success code or a redirect.">A form</Option>

<Hint>Try each request and read the number in the response.</Hint>
<Hint>Codes starting with 4 mean the request asked for something the server can't give.</Hint>
<Hint>Example: a link with a typo in it often leads to a 404 page.</Hint>

</Explore>


```js
assert($$('.shop li').length === 3, 'Add three li items inside the list.')
```

</Test>

<Hint>Items go between the opening and closing ul tags.</Hint>
<Hint>Each item is its own li element.</Hint>
<Hint>Example: a list of two drinks has two li elements, each with a drink inside.</Hint>


</Solution>

</Code>
