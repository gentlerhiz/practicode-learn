# UI/UX Product Design

*Syllabus v0.1 (draft for practitioner review) · Licensed under CC BY-SA 4.0*

> **Design professional digital products, from research to interactive prototype.**

| | |
|---|---|
| **For** | Beginners, career switchers, developers and marketers moving into design |
| **Prerequisites** | None. Curiosity about people is the main requirement. |
| **Estimated effort** | ~110 hours across 11 modules plus a capstone |
| **Tools** | Figma, FigJam, Figma Community, Iconify, Unsplash, Autoflow |
| **Primary alignment** | [ISO 9241-210:2019](https://www.iso.org/standard/77520.html) human-centred design activities |
| **Also aligned to** | UK Design Council Double Diamond · WCAG 2.2 AA · SFIA 9: URCH@2–3, HCEV@2–3, USEV@2, ACIN@2 · benchmarked against the scope of the Google UX Design Certificate |
| **Credential** | PractiCode Learn Certificate: UI/UX Product Design (Open Badges 3.0) |

## By the end, you can

1. Plan and run user research, and synthesise the findings into clear problem statements.
2. Structure information and map user flows.
3. Move from sketches to wireframes to high-fidelity designs in Figma.
4. Build reusable components and a small design system.
5. Prototype interactions and run usability tests.
6. Design accessibly (WCAG 2.2 AA) and hand off cleanly to developers.
7. Present two portfolio case studies.

## ISO 9241-210 coverage

| ISO 9241-210 activity | Double Diamond phase | Modules |
|---|---|---|
| Understand and specify the context of use | Discover | 1, 2 |
| Specify the user requirements | Define | 3, 4 |
| Produce design solutions | Develop | 5, 6, 7, 8, 9 |
| Evaluate the designs against requirements | Deliver | 10, 11 |

## Modules

| # | Module | Key outcomes | Project |
|---|---|---|---|
| 1 | **What UX really is** · *Free* | Explain human-centred design and the Double Diamond; tell UX and UI apart; critique an everyday product | A UX critique of an app you use daily |
| 2 | **User research** | Plan research; write unbiased interview questions; run interviews and surveys; recruit ethically | Interview three people about a real problem |
| 3 | **Synthesis** | Build affinity maps, personas, empathy maps and journey maps; write problem statements and "How might we" questions | A research synthesis board in FigJam |
| 4 | **Information architecture and user flows** | Card-sort; build sitemaps; map task flows | A user flow for the core task |
| 5 | **Sketching and wireframes** | Use Crazy 8s and low-fidelity wireframes in FigJam and Figma | Wireframes for the core flow |
| 6 | **Visual design** | Apply type scales, colour, layout grids, hierarchy and imagery (Unsplash, Iconify) | A high-fidelity key screen |
| 7 | **Components and design systems** | Use auto layout, components, variants and tokens; use Figma Community resources well | A mini design system |
| 8 | **Interaction and prototyping** | Build prototypes with smart animate and micro-interactions; use Autoflow for flow diagrams | A clickable prototype |
| 9 | **Accessible design** | Design for contrast, target size, focus order and reduced motion against WCAG 2.2 | An accessibility review of your own design |
| 10 | **Usability testing and iteration** | Write a test plan; moderate tests; rate severity; iterate | Test with five people, then iterate |
| 11 | **Handoff and working with developers** | Use Dev Mode; write specs; document edge and error states | A developer-ready handoff file |
| ★ | **Capstone** | Two end-to-end case studies, one of them for a real organisation | A portfolio with two case studies |

## Assessment

In-lesson critique and choice tasks with expert feedback, module mastery checks, rubric-marked projects (research quality, rationale, visual craft, accessibility) and a capstone. Mentor-plan learners get live design critiques.

## Device notes

Research, theory and critique lessons work on a phone. Figma runs in a browser, but design work needs a computer with a mouse or trackpad.
